# 《程序员的 README》：学校没教的那一半

2024 年 10 月读完。

会写代码只是程序员工作的一部分。进入真实项目以后，还要接手旧代码、评审变更、发布服务、值班排障，也要学会和团队一起面对事故。这些事学校很少系统地教，大多靠工作里一点点碰。

书中关于故障回顾的内容让我印象较深。好的复盘不是找一个人背锅，而是把当时的条件、判断和系统缺口留下来，供后面的人学习。有些团队会一起阅读过去的复盘文档，甚至把总结公开给社区。这种做法比一句“以后注意”有价值得多。

另外还有影子流量：把真实请求复制到候选系统，对比新旧响应，但只把生产系统的结果返回给用户。它很适合迁移和大改场景，因为测试环境很难还原真实流量的复杂性。看到这里会觉得，成熟工程实践的重点不是相信自己不会犯错，而是尽量让错误更早、更安全地暴露。

这本书像一份职业说明书。技术细节会更新，负责地交付、沟通和复盘却不会很快过时。
